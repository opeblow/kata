A plugin for Hermes Agent

Do it three times.
Approve it once.

Kata watches the tool calls your agent makes, finds the multi-step routines it keeps rediscovering, and, only after you review and approve them, compiles each one into a single deterministic tool. No model calls between steps. Every run traced.

Install Kata Read how it works
hermes plugins install kata
01 / The problem

Agents rediscover the same workflow every single time.

Hermes remembers facts and grows skills. But when it searches, reads and checks the same way for the fortieth time, it still asks the model what to do after every step. That costs tokens, time and, occasionally, a step done differently from last time.

Cost

Each step between tool calls is a full model request carrying the whole context.

Latency

A three-step routine waits on the model twice before it can finish.

Drift

A prompt or skill describes the routine. Nothing guarantees the agent follows it the same way.

02 / How it works

From observed behaviour to an audited tool, with you in the middle.

Every stage uses documented Hermes plugin interfaces: lifecycle hooks, tool registration and in-process dispatch.

  1. 01Observe

    Record real tool calls

    The post_tool_call hook stores each call with its turn and conversation. Secrets are masked before anything touches disk. Model requests are timed from post_api_request.

  2. 02Discover

    Find routines, not coincidences

    Only contiguous, successful calls inside one turn count. A routine must recur in separate conversations, and a template built without one example must reproduce that example exactly.

  3. 03Validate

    Prove it offline

    Twelve checks run against recorded history with a stub dispatcher: exact replay, call-for-call execution, schemas, injected failures and timeouts, secrets, tool availability.

  4. 04Approve

    Nothing activates on its own

    You see the steps, the data flow, permissions, schemas, side effects and evidence. Approve it in /kata or the dashboard tab. Rejections are final.

  5. 05Run

    One call, every step traced

    The approved routine becomes a tool the agent calls once. It stops at the first failure, retries only read-only steps, and becomes stale if an underlying tool changes.

05 / Safety

Built to be trusted with your tools.

Kata only ever replays what you already did, only after you say yes, and only through Hermes.

Explicit approval, always

Observed behaviour never becomes an active tool on its own. Approval re-runs validation and is written to an audit log.

No silent side effects

Steps that reach outside the machine, or that Kata cannot classify, ask you on every invocation with a fresh approval key. They are never retried.

Least privilege

A kata can call only the tools in its own steps, through Hermes's dispatcher, with Hermes's own checks.

No secrets in tools

Credentials are masked at record time. A routine whose fixed arguments contain a secret is never compiled.

Drift aware

Tool schemas are fingerprinted at approval. A change marks the kata stale and unregisters it. Repeated failures suspend it.

Local only

History lives in one SQLite file in your Hermes profile. Kata makes no network calls of its own.

06 / Start

Install it and keep working.

Kata stays quiet until a routine has really repeated. Then it asks.
